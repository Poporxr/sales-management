If the project is empty, create an appropriate Python project structure.

- `main.py` — application entry point

- `ui/pages/` — main screens

## Application Architecture

Use ONE main `CTk` application window.

Do not create a separate root window for each page.

Use frames/classes for individual pages and provide a simple centralized navigation mechanism.

Dialogs/modals may use `CTkToplevel`.

Structure the code so that real services and SQLite can be connected later without rewriting the UI.

Do not put the entire application into `main.py`.

## Important Future Architecture

Do NOT implement this yet, but structure the code with these future requirements in mind.

The production MVP will use local SQLite and remain fully functional without internet.

Normal POS operations must never depend on a remote API.

Eventually:

- products will be stored locally
- sales will be written locally
- checkout will deduct stock locally
- receipts will be generated locally
- sensitive management changes will create audit records
- manager credentials/PIN will be stored securely
- old sales must retain the price at which an item was originally sold, even if the current product price changes later
- audit records should be effectively append-only through the application

The application may eventually support cloud synchronization and multi-store management, but DO NOT build that now.

Do not add FastAPI, PostgreSQL, authentication servers, synchronization infrastructure, or a web dashboard.
